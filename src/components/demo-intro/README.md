# 匠ネットワークの紹介設計

## 実装前の設計メモ

- デモ名：匠ネットワーク。協力業者の比較・協業マッチング・選定アシスタント。
- 見せ切る操作：ランキングから業者を選び、5項目の評価と施工実績を確認する。案件条件から工種別の推奨協力体制を見る。要望を文章で相談し、候補と選定理由を読む。
- 焦点：ランキングの選択行、評価内訳、案件の必要工種、推奨業者と適合度、相談文、候補名と提案理由。
- 利用者の人数：紹介では1人。担当者が同じWebアプリの機能を順に確認する。
- 本物の画面：業者スコアリング、協業マッチング、選定アシスタントの3タブ。PCのWebアプリ。スマホ入力専用画面や承認者用画面は存在しない。
- つながりの種類：一人の操作の段階。
- 選んだ型：B（単一画面型）。前後の状態や同じ画面のカードを左から右へ見せる。
- 主役：場面表のカード1〜2枚のみ。別端末や別担当者を置かない。
- 禁止する見え方：建設の現場→内勤→責任者のリレー、書類の飛び移り、発注や承認まで完了する演出、実AIが動いているという表示。
- 機能上の制約：案件条件と推奨体制は現在固定サンプル。入力や自動計算が新たに実行されたように見せず、条件と結果を確認する。アシスタントは本体と同じルールベースのサンプル応答を表示する。
- 段階数・秒数の根拠：比較の根拠、工種ごとの体制、相談への理由付き提案という3機能の核を省かない。評価内訳と提案文には読む時間を確保し、前後比較は短くする。下表の合計から尺を決める。

## 実装と差し替え

`DemoIntro.jsx` は社内ナレッジ版の単一時計・停止再開・幅追従を移植する。
`story.js` はこの台本専用。`IntroScreens.jsx` は本体の表示部品を紹介モードで再利用する。
紹介に操作イベント、API呼び出し、保存処理を持たせない。
スタイルは `.ti-` と紹介領域内に限定する。

本体の `ScoringView`、`MatchingView`、`AssistantView` を再利用する。紹介だけ一覧を上位5社に絞り、詳細・条件・候補の文字を拡大する。
チャット回答は本体と同じ純粋関数 `generateDemoResponse` で固定の質問から生成する。紹介では `/api/chat` を呼ばない。
サンプル応答の候補名と選定理由は変更せず、回答の導入文だけを省略して読みやすくする。

## 再生と導線

- 一本のrequestAnimationFrame時計から、場面とカメラを導く。停止時に時計を保持し、再開は同じ位置から進む。
- 子画面のグラフアニメーション、CSSアニメーション、チャットの自動スクロールは紹介モードで無効にする。
- ページ非表示中は停止する。離脱時はフレーム、イベント、ResizeObserverを解除する。
- モーション低減時は最後の提案を静止表示する。設定変更とサイズ変更に追従する。
- 紹介の下のボタンから `#score`、`#match`、`#assist` へ進む。「紹介を見る」で戻ると再生は先頭から始まる。
- 別タブへ移ると各体験コンポーネントはアンマウントされる。従来と同様、その場の会話は保持しない。
